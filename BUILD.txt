WHAT THIS IS
  Cumulative snapshot (deploy this ONE zip). Migrations 0001-0111. App change
  (admin sync UI + i18n) + the deploy-hardening-2 workflow.

THE PROBLEM
  "Synced 187 rows for 2 patients" was reported even though nothing reached
  REDCap (empty REDCap Logging page). Two bugs:
   1. The message used `rows` = rows BUILT from the DB, not `imported` =
      REDCap's confirmed count. So it showed a number even if 0 were imported.
   2. The admin route returns HTTP 207 when the import has errors; 207 counts
      as res.ok, so the client treated it as success and HID the errors.

WHAT CHANGED (app/[locale]/clinician/admin/page.tsx + clinician.researchExport i18n)
  The sync result now:
   - on success shows REDCap's confirmed count: "Imported {imported} of {rows}
     rows for {patients} patients into REDCap." (syncResult)
   - if the import reported errors OR imported < rows, shows an ERROR box with
     REDCap's actual message: "REDCap accepted only {imported} of {rows} rows —
     the import reported a problem: {message}" (syncPartial / syncNoDetail).
  New i18n keys syncPartial, syncNoDetail (en/da/sv/nb; da/sv/nb first-pass).
  syncResult reworded. Parity 1724 keys.

WHAT TO DO
  Deploy, then re-run "Sync to REDCap now". It will now show what REDCap
  actually said. The empty Logging page means the import never landed — almost
  certainly:
   - REDCAP_API_URL is not the API endpoint (it must look like
     https://<your-redcap-host>/api/  — with /api/ , not the project page URL), or
   - REDCAP_API_TOKEN is from a different project (tokens are per-project) or
     expired.
  The new error message will distinguish these (e.g. an HTTP 403 = bad token; an
  unparseable/HTML response = wrong URL).
