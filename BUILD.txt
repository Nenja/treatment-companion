BUILD: itb-therapy-track   (ITB + BTX in parallel — slice 1)
=========================================================================
WHY THIS IS SLICE 1
Intrathecal baclofen (ITB) is a continuous, titrated pump therapy, not a
peak-effect cycle. And in the current code EVERY "resolve the patient's active
cycle" RPC (goal creation, weekly check-in, the physio submits) assumes a
single active cycle — so adding a second concurrent active treatment_cycle for
ITB would silently break the botulinum-toxin (BoNT) flow.

So ITB is introduced here as its OWN entity, running in parallel with the BoNT
cycles and touching none of that logic. This slice = the ITB therapy + its dose
titration log. ITB *goals* (which reuse the cycle/goal/check-in machinery and
therefore need every active-cycle resolver made modality-aware) are slice 2.

WHAT THIS BUILD DOES
- Migration 0079: itb_therapy (one active per patient) + itb_dose_change
  (titration log, dose in mcg/day) + RLS + start_itb_therapy /
  log_itb_dose_change RPCs.
- New ITB track on the clinician patient page (left column):
  - No active therapy -> a compact "Start ITB track" card.
  - Active -> current dose, start date, a dose-titration timeline, and a
    "Log dose change" modal.
  - No week/peak/video logic — ITB is continuous.

DEPLOY
