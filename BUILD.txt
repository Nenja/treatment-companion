BUILD: therapist-gas-rating   (GAS-aware therapist rating)
=========================================================================
MIGRATION: 0084_physio_gas_value.sql  — RUN THIS (after 0083).

WHAT THIS BUILD DOES
The therapist now rates a GAS goal against its outcome levels/anchors — the
same five-level picker the patient uses — instead of a bare 0–10 scale. This
fixes the old lossy behaviour where a GAS goal's 0–10 value was cast to a
−2..+2 level. NRS goals are unchanged (still 0–10).

SCHEMA (0084)
- physio_goal_rating + gas_value int (−2..+2 check).
- new type physio_goal_rating_input_v3 (adds gas_value); submit_physio_assessment
  recreated with v3 (validates nrs 0–10 and gas −2..+2 independently, each only
  when present).

CLIENT
- Therapist progress form renders the GAS picker (with the goal's anchors) for
  GAS goals and the 0–10 picker for NRS goals; sends nrsValue XOR gasValue by
  kind.
- Both chart overlays (therapist page + clinician page) now plot GAS goals from
  gas_value directly and NRS goals via nrsToGas(nrs_value), and ignore
  flag-only rows. (Removes the old NRS→GAS cast on the clinician page.)

DEPLOY
1. Run 0084 in the Supabase SQL editor (after 0083).
2. Unzip; push to GitHub; Vercel builds. Page count 60.
