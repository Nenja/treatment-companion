WHAT THIS FIXES
---------------
The patient check-in crashed to the global error screen ("Something went wrong /
The app ran into an unexpected problem...") with, in the browser console:

    Error: Minified React error #310
    (= "Rendered more hooks than during the previous render")

Root cause: a React rules-of-hooks violation in app/[locale]/checkin/page.tsx.
The `confirmLeave` useState (added with the check-in Cancel dialog) was declared
BELOW the component's early returns (ThanksView / CheckinSkeleton / null). On the
loading -> loaded transition the number of hooks called changed by one, which
React forbids, so it threw and the whole app fell back to app/global-error.tsx.

Why it looked specific to test patient 1: the crash only happens for a patient
whose check-in actually loads content. test1 has a pending weekly prompt, so its
check-in renders the steps and hits the transition. Patients with no pending
prompt return null earlier and never reach the extra hook, so they don't crash.
This was a pre-existing latent bug; the recent re-seed didn't cause it, it just
made test1 the account you opened the check-in on. (The GAS goal was a red
herring — the GAS check-in code itself is correct.)

THE FIX
-------
Moved `const [confirmLeave, setConfirmLeave] = useState(false);` up to sit with
the other state hooks, ABOVE every early return, so the hook order is identical
on every render. Also corrected a stale code comment that still said the cancel
flow had "no confirmation dialog". Only file changed: app/[locale]/checkin/page.tsx.
