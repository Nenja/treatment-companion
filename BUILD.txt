WHAT THIS IS
  Cumulative snapshot (deploy this ONE zip). CI workflow + docs only — NO app
  code change since admin-overview-search-1, so no rebuild was needed.
  Migrations 0001-0111.

THE PROBLEM (2026-06-16)
  Two production deploys per commit in Vercel: a `main` ~1 min build (worked)
  and a `HEAD` ~12 s prebuilt deploy from the GitHub Action (500'd: "Your
  project's URL and Key are required"). The live alias flapped between them.
  Causes:
   1. Vercel's automatic production deploys were never turned off, so BOTH
      Vercel's own git build AND the Action deployed production.
   2. The Action's prebuilt build inlined BLANK NEXT_PUBLIC_SUPABASE_* values:
      those are baked in at build time, the CI build gets env via `vercel pull`,
      and `vercel pull` does NOT download vars marked "Sensitive" in Vercel.

WHAT CHANGED HERE
  .github/workflows/deploy.yml now FAILS CLOSED:
   - after `vercel pull`, aborts if NEXT_PUBLIC_SUPABASE_URL / _ANON_KEY are
     missing/blank (with a message telling you to un-mark them Sensitive);
   - after `vercel build`, aborts if the built output contains no Supabase URL.
  So a blank/500 bundle can never reach production again — the last good build
  stays live instead.
  docs/STAGING-AND-CI-GATE.md gains a "Troubleshooting" runbook with the cause
  and the ordered fix.

*** YOUR DASHBOARD STEPS — IN THIS ORDER (do not reorder) ***
  1. Vercel → Settings → Environment Variables: make NEXT_PUBLIC_SUPABASE_URL
     and NEXT_PUBLIC_SUPABASE_ANON_KEY exist for Production and NOT "Sensitive".
     (Server secrets — service role, REDCAP token, CRON_SECRET — can stay
     Sensitive; they're runtime, not inlined.)
  2. Deploy this zip; let the Action run; CONFIRM treatment-companion.vercel.app
     works. If a var is still Sensitive, the Action now fails loudly instead of
     shipping a 500 — fix per its error and re-run.
  3. ONLY THEN, to stop the double-deploy: Vercel → Settings → Build and
     Deployment → Ignored Build Step =
       if [ "$VERCEL_ENV" = "production" ]; then exit 0; else exit 1; fi
     This cancels Vercel's own production git builds (so only the gated Action
     deploys prod) while still building Preview/staging. After this you should
     see ONE production deploy per commit (HEAD), not two.

  Always use treatment-companion.vercel.app — never the per-deploy
  ...-<hash>.vercel.app URLs (those change every deploy by design).
