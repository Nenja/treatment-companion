BUILD - fix-export-guidance-0111   (hotfix: research export RPC column error)

WHAT THIS IS
  Cumulative snapshot on top of retire-dev-scenarios-1. ONE new migration
  (0111) — a create-or-replace of export_research_dataset(). No schema/data
  change, no app change. Migrations now 0001-0111.

THE BUG (hit live during the production sync test)
  "Sync to REDCap now" failed with:
    export_research_dataset failed: column m.guidance does not exist
  Migration 0009 moved `guidance` from the per-muscle table to the SESSION
  (treatment_session), but the export RPC in 0106 still read `m.guidance`
  (muscle_injection). It surfaced only now because the JS row-builder tests
  exercise lib/redcap, not the SQL RPC, so the bad column was never executed.

THE FIX (supabase/migrations/0111_fix_export_guidance.sql)
  create-or-replace export_research_dataset() reading `s.guidance` (the
  treatment_session alias already joined in that subquery) instead of
  `m.guidance`. Everything else identical to 0106.

*** YOU MUST RUN 0111 ***  (standalone copy in outputs)
  Run 0111_fix_export_guidance.sql in the STAGING Supabase SQL editor first,
  then PRODUCTION. Until you do, the REDCap sync (button + cron) will keep
  failing with the m.guidance error. No data migration — it just redefines the
  function.

VERIFIED (Method-D, throwaway Postgres + full staging schema)
  - Negative control: calling the 0106 version reproduced
    "column m.guidance does not exist".
  - After applying 0111: export_research_dataset() returns [] with no error
    (and since Postgres validates all columns at plan time even with zero rows,
    this also confirms no OTHER stale column references remain).

FOLLOW-UP (logged in docs/ROADMAP.md)
  The SQL RPCs aren't covered by the JS tests. A Method-D / CI smoke-call of
  export_research_dataset() would catch this class of error before shipping.
