WHAT CHANGED (three things, all from the page-by-page review)
---------------------------------------------------------------------
1. NRS goals no longer show GAS cut-offs in setup.
   - The clinician now configures an NRS goal with just the 0-10
     question + direction. The four cut-off inputs are gone from both
     "Record a goal" (new-goal) and "Approve a suggestion".
   - Done as OPTION B (UI-only): the database still requires four
     cut-offs per NRS goal and the check-in RPC still derives an
     (unused) GAS level from them, so instead of rewriting the critical
     weekly check-in path, the app now sends fixed default cut-offs
     (1/3/5/7) behind the scenes. The graph and the "since last visit"
     verdict already use the raw 0-10 score + direction, so the derived
     GAS stays the unused byproduct it already was.
   - NO schema change, NO check-in change. Cut-off columns keep getting
     default data.

2. A suggestion can now be approved as a GAS goal (not only NRS).
   - The approve form has a measurement-model toggle (0-10 scale /
     Descriptive levels) + five anchor inputs.
   - Backed by ONE new additive RPC: approve_suggestion_gas
     (migration 0067). Needed because set_suggestion_status forbids
     setting 'active', so GAS approval needed its own approve path.

3. /demo deleted (no-auth sandbox, as requested). Orphaned helpers
   removed too (components/clinician/GasCutPoints.tsx, lib/demo/).

Also fixed a PRE-EXISTING build blocker (not caused by the above):
statically prerendering /clinician/patient hit a Next 15 React Server
Components client-manifest bug. Added a tiny segment layout that forces
that one auth-gated route dynamic (export const dynamic =
'force-dynamic'). It's the correct behaviour for a session-only page
anyway, and no other route is affected.


DEPLOY STEPS
---------------------------------------------------------------------
1. RUN THE MIGRATION (required for the GAS suggestion-approval option):
   In the Supabase SQL editor, run:
       supabase/migrations/0067_approve_suggestion_gas.sql
   It is additive (create or replace), changes no tables, and is safe
   to re-run. If you skip it, approving a suggestion as GAS will error;
   NRS approval and everything else still works.

2. Deploy the code: push the repo to GitHub -> Vercel as usual.
   No environment-variable changes. (NEXT_PUBLIC_ENABLE_DEMO is no
   longer used by anything.)
