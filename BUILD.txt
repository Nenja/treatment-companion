WHAT THIS ADDS:
  A new automatic check that directly targets the bug that broke your pages this session — the app
  asking the database for a column that doesn't exist (e.g. length_weeks), or one from a migration
  you hadn't run yet (the consent columns).

  How it works (all inside CI, no real database involved):
    1. The migrations check applies all the SQL to a throwaway database (as before).
    2. It then takes a snapshot of that database's shape.
    3. scripts/check-schema-contract.mjs reads every place the app asks the database for data
       (.from('table').select('columns') and .rpc('function')) and confirms each table, column and
       function actually exists in the snapshot.
  If the app ever references something that isn't there, CI goes red and names it — before it can
  reach a real page.
