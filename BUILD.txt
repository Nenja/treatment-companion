WHAT CHANGED THIS INCREMENT
  Runtime RLS-denial test suite (highest-value check for real patient data)
    - supabase/ci/rls-test-setup.sql - turns the throwaway CI Postgres (real
      bootstrap + all migrations) into one where RLS can be exercised:
      auth.uid() reads a per-connection GUC (test.uid) so any user can be
      impersonated; authenticated/anon get Supabase-like table grants so a
      denial is RLS and not a missing GRANT; an _assert() raises on a failed
      expectation; deterministic fixtures (2 patients, a clinician with an
      active session for A only, an admin, therapist notes, a study).
    - supabase/ci/rls-tests.sql - the assertions. Each impersonates a user via
      SET ROLE + set_config('test.uid',...) so the REAL policies decide
      visibility. Coverage:
        T1 patient A sees only their own patient row
        T2 patient A cannot read patient B's profile
        T3 patient reads only their OWN care-team notes, never another's
        T4 clinician WITH an active session sees A, never B (+ notes)
        T5 a STALE session (>1h idle) grants no access
        T6 anonymous (no JWT) sees nothing
        T7 study/study_membership are admin-only (+ admin positive control)
      Every denial is paired with a positive control so a "deny everything"
      bug cannot pass silently.
    - supabase/ci/run-rls-tests.sh - run the suite against a local Postgres.
    - .github/workflows/ci.yml - new "RLS-denial tests" step in the migrations
      job (after the schema snapshot). Fails the build on any RLS regression.

  Verified here:
    - All assertions pass on a throwaway PG16 (real bootstrap + all migrations).
    - NEGATIVE CONTROL: injecting a `using(true)` patient SELECT policy makes

>>> FINDING - PLEASE DECIDE: care-team notes are PATIENT-READABLE <<<
  The docs (HANDOVER 5.13, TRANSFER_PROMPT) say the physician->therapist
  handoff note and therapist notes are "never patient-visible". That was true
  at migrations 0088/0095, but migration 0096_patient_care_team_notes
  DELIBERATELY added a patient self-read on treatment_handoff,
  goal_handoff_note, and therapist_note (patient_id = current_patient_id()),
  citing the patient's GDPR right of access. So a patient CAN read the notes
  about their own care (never another patient's - that isolation is intact and
  tested). Not a code bug - 0096 is intentional and self-documenting - but it
  contradicts the stated invariant and has clinical-privacy weight (anyone
  writing such a note should know the patient can read it). HANDOVER 5.13 is
  corrected. DECISION: confirm patient-readable is intended, OR treat
  author-private care-team notes as a product change to make.
