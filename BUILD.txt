BUILD: video-playback
=========================================================================
WHAT THIS BUILD DOES
Clinicians can now PLAY BACK the short videos patients record at check-in.
Until now the clinician view only showed a COUNT of videos (indicator
only) with no way to watch them. This makes each clip playable.

** NO DATABASE MIGRATION. ** Frontend only. It reuses the private
`goal-videos` Storage bucket and its policies from migration 0062 — which
already grant a clinician read access to the videos of patients they have
an active session with. So the player works from the clinician's own
session; no service role and no new SQL.

CHANGES
- NEW lib/supabase/goalVideo.ts — useGoalVideoUrl(path): creates a 1-hour
  signed URL for a `goal-videos` object (refetches before it expires).
- NEW components/clinician/VideoPlayerModal.tsx — accessible modal
  (Esc / backdrop / button to close) that streams the signed URL in a
  native <video controls playsInline> element, with loading / error /
  unsupported states.
- components/clinician/VisitChanges.tsx — the "since last visit" summary
  (which already showed a video count) now lists each clip as a play
  button labelled by goal + week, and opens the player. videoPath was
  already present in the clinician data per rating, so no data-layer change.
- i18n: visitChanges.videosHeading / videoLabel / videoTitle +
  clinician.video.{close,loading,error,unsupported} (en + da).
  Parity 1072 == 1072.

DEPLOY
1. Unzip; push to GitHub; Vercel builds on push. Page count unchanged (60).
2. No SQL to run. (Confirm 0062 — the goal-videos bucket — is already
   applied; it is on any current deploy, since video capture already works.)

HOW TO CONFIRM IT WORKED (needs a real browser + Supabase Storage + a
recorded video — cannot be tested in this environment)
- Use a patient who recorded a video in the current visit window (e.g. the
  test1 seed has video enabled on a goal). Unlock that patient.
- On the clinician patient view, under the "since last visit" summary, you
  should see a "Videos" row with a play button per clip ("Goal · Week N").
- Tap one: a modal opens and the video streams.
- Negative check: a clinician WITHOUT an active session for that patient
  should not be able to load the video (the Storage policy denies the
  signed-URL request).

QA FLAGS (cannot be verified here)
- Storage signed-URL creation, RLS denial for non-session clinicians, and
  actual streaming need a real Supabase + browser.
- Real-device playback (iOS Safari / Android Chrome): codecs and video
  orientation should be checked on hardware.
- Scope: playback is currently surfaced for the since-last-visit window.
  Videos recorded earlier in the cycle aren't listed there yet — a per-goal
  playback entry point is a small follow-up (noted in HANDOVER section 8).
