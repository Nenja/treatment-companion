PART B - DATABASE + EDGE FUNCTION (Supabase dashboard / SQL editor)
These steps are NOT part of the GitHub -> Vercel flow. I cannot do or

============================================================
Goal: make the weekly reminder actually fire on each patient's chosen day,
automatically, every day.

STEP 1 - Deploy the reminder function (if the new version isn't live yet)
  The repo file supabase/functions/send-checkin-notifications/index.ts is the
  weekday-aware version. In the Supabase dashboard:
    Edge Functions -> send-checkin-notifications -> paste the file's contents
    -> Deploy.
  (If the function doesn't exist yet, create it with that name first.)

STEP 2 - Check the function's secrets are set
  Dashboard -> Edge Functions -> (Secrets / Settings). You should have:
    CRON_SECRET, FCM_SERVICE_ACCOUNT, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY
  (CRON_SECRET and FCM were set when push was tested on your phone.)

STEP 3 - Store two Vault secrets BY HAND (real values; do NOT commit these)
  Dashboard -> SQL editor, run once (replace the placeholders):

    select vault.create_secret('PASTE-YOUR-CRON-SECRET-HERE', 'cron_secret');
    select vault.create_secret(
      'https://YOURPROJECTREF.supabase.co/functions/v1/send-checkin-notifications',
      'checkin_fn_url'
    );

  (Find YOURPROJECTREF in your function URL. If a name already exists, you
  stored it before - skip it, or update it via vault.update_secret.)

STEP 4 - Run the migrations in the SQL editor
  - 0103_allow_sv_nb_locales.sql  (only if you haven't already; safe to re-run)
  - 0104_schedule_checkin_notifications.sql  (NEW - the daily schedule)
  If 0104 errors on "CREATE EXTENSION", enable pg_cron and pg_net first in
  Dashboard -> Database -> Extensions, then re-run 0104.

STEP 5 - Test WITHOUT sending anything (dry run)
  In a terminal (or any REST tool), with your real values:

    curl -X POST \
      'https://YOURPROJECTREF.supabase.co/functions/v1/send-checkin-notifications' \
      -H 'Authorization: Bearer PASTE-YOUR-CRON-SECRET-HERE' \
      -H 'Content-Type: application/json' \
      -d '{"dryRun": true}'

  This returns the PLAN (which patients would be notified today) and sends
  nothing. When you're happy, the daily 07:00 UTC job (from 0104) will run it
  for real. To send yourself one real test push:
    -d '{"testProfileId": "<your patient profile id>"}'

NOTE ON TIMING: 0104 runs daily at 07:00 UTC (~08:00-09:00 Danish time). The
function decides each day who is due based on their chosen weekday, so daily
is correct. Change the cron expression in 0104 if you want another time.
