WHAT CHANGED
------------
Test patient 1's optional check-in video now appears on the CURRENT check-in,
instead of you having to open an earlier ("previous"/catch-up) check-in to find it.

Why it was off: the app shows the optional video at weeks 6-8 of a cycle. test1's
cycle started 8 weeks ago with weeks 1-7 already completed, so the *current* week
(by date) was week 8-9 — at or just past the window — and week 8 showed up as an
overdue catch-up. So the video landed on a previous/catch-up check-in, not the
current one.

Fix: test1's cycle now starts 5 weeks ago and completes weeks 1-5, so the current
pending check-in is week 6 — comfortably inside the 6-8 window. The current
check-in stays in-window for about 3 weeks (the current week walks 6 -> 7 -> 8)
before it drifts out again; re-running the seed resets it.

- supabase/migrations/demo_seed_test_patients.sql  (block 1: cycle start -56 -> -35,

- lib/dev/scenarios.ts  (one dev-launcher description: "~week 8" -> "~week 6")

HOW TO APPLY
------------
1. In the Supabase SQL editor, run the attached demo_seed_test_patients.sql
   (idempotent — it wipes & rebuilds each patient). That reseeds test1 with the
   week-6 current check-in. This is all you need.
2. Optional: if you reseed using the dev launcher's "reset" (dev_reseed_all)
   instead of the SQL file, run the updated 0066 first so dev_seed_b1 matches,
   then use the launcher.
3. No app redeploy needed for the data change. (The only code change is a dev-only
   description string; push the zip if you want it, but it's not required.)

HOW TO CONFIRM
--------------
1. Sign in as test1@example.com.
2. Open the current check-in from the home screen (it should be "week 6").
3. On the hand goal's step ("...open my hand..."), the optional video recorder
   appears right there — no need to open a previous/earlier week.
