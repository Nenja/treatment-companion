BUILD - deploy-hardening-2   (inject build-time public env from CI secrets)

WHAT THIS IS
  Cumulative snapshot (deploy this ONE zip). CI workflow + docs only — NO app
  code change since admin-overview-search-1. Migrations 0001-0111.

WHY
  After making NEXT_PUBLIC_SUPABASE_URL/_ANON_KEY non-Sensitive, the prebuilt
  deploys STILL 500'd. So we stop relying on `vercel pull` for the build-time
  public vars (it skips Sensitive vars and is scope-sensitive) and instead
  write them straight into the build's env file from GitHub repo secrets.

WHAT CHANGED
  .github/workflows/deploy.yml: after `vercel pull`, the deploy step now
   - fails fast if the two repo secrets aren't set;
   - removes any pulled (possibly blank) NEXT_PUBLIC_SUPABASE_* lines from
     .vercel/.env.production.local and writes the secret values (first
     definition wins in a dotenv file, so the blank must go);
   - builds, then refuses to deploy unless the built output contains a
     Supabase URL (still fail-closed).

*** REQUIRED ONE-TIME SETUP ***
  GitHub → repo Settings → Secrets and variables → Actions → New repository
  secret, add BOTH (use your PRODUCTION Supabase values):
    NEXT_PUBLIC_SUPABASE_URL
    NEXT_PUBLIC_SUPABASE_ANON_KEY
  (These are public — they ship in the browser bundle — so they're safe as CI
  secrets. Server-only keys stay in Vercel.)

*** IMPORTANT — this only works once THIS deploy.yml is in the repo ***
  If a 500 persisted after the previous fix, it's likely the updated workflow
  was never uploaded (e.g. a README edit made directly on GitHub ran the OLD
  workflow). Deploy THIS zip so the correct workflow is in place.

TO GET THE SITE BACK UP RIGHT NOW (while setting the above up)
  The active production is the broken prebuilt deploy. Quickest restore:
  GitHub → Actions → "Deploy (production, on green CI)" → ••• → Disable
  workflow; then in Vercel make sure the Ignored Build Step is NOT skipping
  production (empty/default) and Redeploy the latest commit — Vercel's own
  build (the ~1 min one that works) will serve. Re-enable the Action after the
  secrets are set and you've confirmed a prebuilt deploy works.

ORDER ONCE FIXED
