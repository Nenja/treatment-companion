BUILD: session-switching
=========================================================================
WHAT THIS BUILD DOES
Lets a clinician hold several unlocked patient charts open at once and
switch between them WITHOUT re-entering codes, and reopen a patient they
already unlocked TODAY without a fresh code.

** THE CONSENT GATE IS UNCHANGED. ** Visit codes are still patient-generated,
single-use, and short-lived; the 0043 reusable-test-code containment is
preserved verbatim; PRE-VISIT access is NOT added (that decision is parked).
Only two things changed: a clinician may have more than one session open at
a time, and may reopen today's patients without a new code.

CHANGES
- Migration 0073_session_switching.sql:
    * one-active-session-per-clinician unique index -> per-(clinician,patient),
      so several patients can be open at once;
    * unlock_with_visit_code no longer ends your other sessions;
    * touch_clinician_session(p_patient_id) and end_clinician_session(
      p_patient_id) — patient-scoped (the no-arg "all" versions are kept);
    * reopen_session(p_patient_id) — reopen a patient YOU unlocked today, no
      new code (authorized only by your own session from today);
    * list_my_sessions() — today's sessions for the switcher.
  The 1-hour inactivity auto-lock (RLS) is unchanged.
- lib/supabase/clinicianSession.ts: "current" session now = most-recently-
  active; touch/end take an optional patientId; new useMySessions,
  useSwitchSession, useReopenSession.
- Clinician entry page (/clinician): no longer auto-redirects into the last
  patient; shows a SWITCHER — "Open patients" (switch back, no code) and
  "Seen earlier today" (reopen, no code) — above the code form. A new code
  still goes straight to the patient view.
- Clinician patient page: "End visit" ends only the current patient (others
  stay open) and returns to the switcher; a new "Switch patient" button
  returns to the switcher WITHOUT ending.
- i18n: clinician.session.{switchPatient,open,reopen,openHeading,openHint,
  reopenHeading,reopenHint} (en + da). Parity 1122 == 1122.

DEPLOY
1. Run migration 0073 in the Supabase SQL editor. Standalone copy attached.
2. Unzip; push to GitHub; Vercel builds on push. Page count unchanged (60).

** SECURITY-SENSITIVE — VERIFY ON REAL SUPABASE (cannot be tested here) **
- Single-patient flow unchanged: unlock -> patient view; End visit -> switcher.
- Open two patients (unlock A; "Switch patient"; unlock B). Both should appear
  under "Open patients"; switching should load the correct chart and must NOT
  cross data between patients.
- Let one session pass 1h idle: it should move to "Seen earlier today" and
  reopen should work WITHOUT a code.
- NEGATIVE CHECKS (the security boundary):
    * a clinician must NOT be able to reopen a patient they never unlocked,
      nor one from a previous day (reopen_session should raise);
    * with no active session, patient data must still be unreadable (RLS).
- "End visit" should end only the current patient. The shared EndSessionButton
  (sub-flows) and the physiotherapist end still end ALL sessions — acceptable,
  but flag if you want those scoped to one patient too.

NOT IN THIS BUILD (parked by decision — HANDOVER section 8)
- Pre-visit prep / roster. Needs consent to move earlier than the visit
  (appointment-scoped, which needs a scheduling concept the app doesn't have,
  or standing opt-in, which needs DPO/regulatory sign-off).
