BUILD: goal-link   (link a goal to an existing lineage — build 2c)
=========================================================================
MIGRATION: 0087_link_goal_to_lineage.sql  — RUN THIS (after 0086).

WHAT THIS BUILD DOES (completes goal versioning)
A correction action. Each goal card gets a "Link" button that opens a modal:
pick another active goal of the same measurement kind, and THIS goal is grafted
onto that goal's lineage as its newest version (the target's current version is
frozen; this goal becomes live). Use it when a continuation was accidentally
started as a separate goal — the two histories then merge into one thread.

RPC (0087): link_goal_to_lineage(source, target)
- clinician-only; same patient; same measurement kind; source must be live and
  a single-version lineage (so no predecessors are orphaned); source and target
  must be different lineages.
- Freeze-then-move ordering keeps the one-live-per-lineage guard satisfied.

VERIFIED LOCALLY
- 0086 + 0087 applied to a throwaway Postgres 16: link merged two NRS lineages
  (target v1 frozen with successor, source became v2 live), the source's rating
  followed its row into the merged history, exactly one live row remained, and
  the guards (same-lineage, kind-mismatch, non-live source) all rejected.
