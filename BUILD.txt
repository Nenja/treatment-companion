BUILD: mandatory-setup
=========================================================================
WHAT THIS BUILD DOES
First-run setup is now MANDATORY, and its accessibility step now includes
the read-aloud toggle. No new background fields — patients still give sex +
date of birth; nothing new is collected from clinicians/physios.

Context: a per-role first-run wizard already existed (OnboardingWizard,
gated on profile.has_seen_intro). It oriented the user, collected patient
sex + DOB, and ended in a "comfort" step that set the visual accessibility
prefs (text size, day/night brightness, layout). It was SKIPPABLE — a panel
at the top of the home screen that was easy to bypass. This build makes it a
gate, and rounds out the accessibility step with read-aloud.

CHANGES
- NEW components/feedback/SetupGate.tsx — mounted once in
  app/[locale]/layout.tsx after PasswordChangeGuard. Until has_seen_intro is
  true it covers the whole app (full-screen) with the role's wizard and NO
  skip button, so setup must be completed before the app is reachable.
    * Defers while must_change_password is true (set-password happens first).
    * Exempt: /login, /signup, /forgot-password, /reset-password, and admin
      accounts.
    * On finish, reveals the app instantly; has_seen_intro flips true so it
      never shows again.
- OnboardingWizard.tsx:
    * "comfort" (accessibility) step gained a read-aloud On/Off toggle
      (writes profile.read_aloud via useSetReadAloud).
    * New props: mandatory (hides the global skip), replayOnly, onComplete.
    * The three per-page home mounts now pass replayOnly, so they only show
      an explicitly-requested tutorial replay (first-run is owned by
      SetupGate). The patient details step keeps its own skip — DOB stays
      optional; mandatory only removes skipping the whole wizard.
- i18n: intro.comfortReadAloud / comfortReadAloudOn / comfortReadAloudOff
  (en + da). Translation parity verified: 1026 == 1026 keys.

DATABASE / MIGRATIONS
- NONE NEW. Migration count stays at 0068.
- A fresh environment still needs 0067 (GAS suggestion-approval) and 0068
  (read_aloud pref) applied; both are additive and safe to re-run.

DEPLOY
1. Unzip; push to GitHub; Vercel builds on push (as usual).
2. No SQL to run for this build (confirm 0067 + 0068 already applied).

HOW TO CONFIRM IT WORKED (needs a real browser + auth — can't test here)
- Create / use a brand-new account: the first login must be forced through
  setup (full-screen, no skip) before the app is reachable.
- Finishing the wizard should reveal the app immediately, and setup must NOT
  reappear on the next login.
- An account flagged must_change_password should hit set-password FIRST,
  then setup.
- /login, /signup, /forgot-password, /reset-password and admin accounts
  should NOT show the gate.
- In the wizard's comfort step, toggling Read aloud On should stick (check
  profile.read_aloud), after which the speaker buttons behave per the
  read-aloud build's device QA (on-device speech, da-DK / en).

QA FLAGS (cannot be verified in this environment)
- Auth/session flow, the gate's redirect ordering vs password change, and
  the "fresh account" path all need a real browser + Supabase auth.
- Read-aloud audio needs real devices (esp. iOS Safari / Android Chrome);
  Danish depends on a da-DK voice being installed.
- Visual rendering of the full-screen gate (z-index over headers/menus,
  small screens) needs a real render.
