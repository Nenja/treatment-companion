BUILD: pre-visit-suggestions   (patient cold-start #1 + #2)
=========================================================================
WHAT & WHY
A newly registered patient could not record anything: signup creates only a
login profile, so there was no patient row (RLS blocked suggestions), and goal
suggestions required a treatment cycle a new patient doesn't have. A suggestion
is just a proposal awaiting approval, so it shouldn't need a cycle — tracking
begins only when a clinician approves it into a real cycle.

MIGRATION 0081 (run this in the Supabase SQL editor; standalone copy attached)
- ensure_patient_row() trigger on profile + backfill: every patient profile now
  has a patient row.
- goal_suggestion.treatment_cycle_id made nullable.
- approve_suggestion (NRS) and approve_suggestion_gas now resolve the patient's
  ACTIVE cycle at approval (suggestion cycle, else active cycle) and refuse if
  there is none — so a goal only becomes trackable once approved into a cycle.

CLIENT
- suggest-goal inserts a cycle-less suggestion (no more "No active cycle" error).
- The patient no-cycle home now has a "Suggest a goal" card explaining the
  clinician will review and set up tracking at the visit — no longer a dead end.

DEPLOY
- Run 0081; unzip; push to GitHub; Vercel builds. Page count 60.

** QA (please verify — can't be tested here) **
- A fresh patient signup gets a patient row.
- From the no-cycle home, "Suggest a goal" completes and saves with no cycle.
- The suggestion shows for the clinician once they have a session; approving
  (NRS and GAS) lands the goal in the active cycle.
- Approving with NO active cycle is refused with a clear error.
- Existing seeded patients still suggest/approve exactly as before.
