Build tag: demo-sandbox

NEW: a no-login, no-Supabase demo sandbox at /demo
Renders the real app components (goal graphs, training panel, rating pickers)
from made-up data, so anyone can click through scenarios WITHOUT logging in or
touching the database.

- Scenario picker: "Going well", "Struggling", "Missed check-ins" (each has
  both an NRS and a GAS goal, training data, and a visit note).
- Two views per scenario:
  * Clinician view — the progress graphs (NRS 0–10 line + GAS bands), the
    Training panel, and a read-only "Since last visit" note.
  * Patient check-in — the real rating pickers (interactive, local-only; the
    demo never saves anything).

ENABLE IT (off by default)
- NEXT_PUBLIC_ENABLE_DEMO=1   (client-only flag)
This is independent of the dev Scenarios launcher's flags, so you can expose
the /demo sandbox (safe — fake data, no auth) WITHOUT enabling the auth
launcher. With the flag unset, /demo shows "disabled".

MIGRATIONS / ENV
- None. No database, no auth, no network. (This differs from the auth
  launcher, which needs migration 0066 + the service role key.)

DEPLOY
- Upload this zip to GitHub -> Vercel. Set NEXT_PUBLIC_ENABLE_DEMO=1 wherever
  you want the demo reachable (it's safe to enable in production if you want a
  public demo, since it has no real data).

How to confirm THIS build is deployed:
- BUILD.txt tag "demo-sandbox".
- With NEXT_PUBLIC_ENABLE_DEMO=1, /demo shows the scenario picker and works
  with no login.
