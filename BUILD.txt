BUILD - e2e-autorun-1   (E2E smoke now runs automatically)

WHAT CHANGED
  One file: .github/workflows/e2e.yml
  It was manual-only (workflow_dispatch). Now it ALSO runs:
    - daily on a schedule (06:00 UTC) - synthetic monitoring; catches prod or
      login breakage even when you haven't deployed anything
    - after a successful PRODUCTION Vercel deploy (deployment_status) - catches
      regressions a deploy introduces
  It is STILL not run on push/PR on purpose: a browser flake must never block a
  normal commit. Your CI "verify" job (typecheck/i18n/test/build) stays the
  push gate. A concurrency group stops overlapping runs.

  No app code, schema, or dependency change. Nothing else in this drop.

DEPLOY
  1. GitHub Desktop: copy .github/workflows/e2e.yml into the repo (overwrite),
     commit, push - to your DEFAULT branch (main). The schedule and the
     post-deploy trigger only take effect from the default branch.
  2. Confirm these are set under Settings -> Secrets and variables -> Actions:
       Variables:  E2E_BASE_URL          e.g. https://treatment-companion.vercel.app
       Secrets:    E2E_PATIENT_EMAIL     a DEDICATED test patient
                   E2E_PATIENT_PASSWORD  that account's password
     (Same ones the manual workflow already needed.)
  3. Optional: trigger it once from the Actions tab ("E2E smoke" -> Run workflow)
     to confirm it's green before relying on the automatic runs.

NOTES
  - DATA: each automatic run completes a weekly check-in as the test patient.
    The check-in test self-skips once that week's prompt is used, so repeats are
    safe - but use a test account you don't also demo with.
  - If your Vercel labels production deployments with something other than
    "Production", edit the environment check in the job's `if:` line.
  - Adjust frequency by editing the cron line (e.g. '0 6 * * 1' = Mondays only).
