BUILD: treatment-modality-seam
=========================================================================
WHAT THIS BUILD DOES
A futureproofing seam for Work Package 4 (baclofen pumps & surgery). The
app's treatment spine assumed every treatment is botulinum toxin; this
makes the model, types, and UI stop assuming that — WITHOUT building any
pump/surgery features yet. It is readiness only.

STRICTLY ADDITIVE & BACKWARD-COMPATIBLE:
- Everything defaults to 'botulinum_toxin'.
- Existing cycles backfill to that default.
- The botulinum-toxin flow is unchanged. No clinical logic branches on the
  new column yet.

CHANGES
- NEW supabase/migrations/0070_treatment_modality.sql:
    * `treatment_modality` enum: botulinum_toxin | baclofen_pump | surgery |
      other.
    * `treatment_cycle.modality` column, NOT NULL DEFAULT 'botulinum_toxin'.
    * Column comment documents the extension plan (per-modality detail
      tables keyed on the cycle; concurrent pathways as parallel cycles).
- lib/types.ts: `TreatmentModality` type + `TREATMENT_MODALITIES`.
- lib/supabase/clinicianPatient.ts: `modality` threaded into the cycle type,
  select, and map (other reads left untouched — they don't need it yet).
- app/[locale]/clinician/patient/page.tsx: a quiet modality pill under the
  cycle date (reads "Botulinum toxin" for every current cycle).
- lib/ehrExport.ts: optional `modality` on the export's cycle input; prints
  a "Treatment modality: ..." line ONLY when non-default, so existing BoNT
  exports are byte-identical.
- i18n: `treatment.modality.*` (en + da). Parity 1065 == 1065.

DATABASE / MIGRATIONS
- RUN migration 0070 (0070_treatment_modality.sql) in the Supabase SQL
  editor. Additive and safe to re-run (guarded enum, add column if not
  exists). Standalone copy attached alongside the zip.
- (A fresh environment also needs 0067, 0068, 0069 applied.)

DEPLOY
1. Run 0070 in Supabase SQL editor.
2. Unzip; push to GitHub; Vercel builds on push. Page count unchanged (60).

HOW TO CONFIRM IT WORKED (needs a real browser + Supabase)
- Existing patients still load; each current cycle shows a small
  "Botulinum toxin" pill under the treatment date on the clinician view.
- The EHR export for a BoNT patient is UNCHANGED (no "Treatment modality:"
  line should appear — it only shows for non-BoNT, of which there are none
  yet).
- Creating a new cycle still works normally (it inherits the default
  modality).

WHAT THIS DELIBERATELY DOES NOT DO (deferred to when WP4 is scheduled —
see HANDOVER section 8)
- No pump/surgery detail tables.
- No modality picker in the new-cycle flow (only BoNT cycles can be created
  today).
- No modality-specific capture or views, and no multi-active-cycle
  (concurrent modality) UI.

These are intentional: the point of this build is to remove the
single-modality ASSUMPTION cheaply now, so the above can be added later
without a rewrite.
