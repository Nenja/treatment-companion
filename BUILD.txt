WHAT THIS IS
  Cumulative snapshot on top of redcap-pii-decision-1. Adds the REDCap sync
  automation (both triggers). New code + UI + i18n + one config file. No DB
  migration. Migrations still 0001-0110.

WHAT'S NEW
  - lib/redcap/buildRows.ts  - pure row/CSV builder, extracted from
    lib/redcapExport.ts (byte-identical mapping logic) so client AND server can
    share it. redcapExport.ts now imports + re-exports from it (the test, which
    imports esc/toCsv/patientRows, is unaffected).
  - lib/redcap/importToRedcap.ts - server-only REDCap API client; chunks rows
    (2000/chunk) and POSTs content=record/csv/flat, overwriteBehavior=normal.
  - lib/redcap/runSync.ts - runRedcapSync(): service client -> 0106 RPC ->
    flatten -> import -> summary. Shared by both triggers.
  - app/api/admin/redcap-sync/route.ts - TRIGGER 1 (admin button). POST,
    signed-in-admin gated (profile.is_admin), writes an admin audit event.
  - app/api/cron/redcap-sync/route.ts - TRIGGER 2 (schedule). GET, CRON_SECRET
    gated (Vercel Cron sends it as Bearer auth).
  - vercel.json - cron "0 3 * * 1" (weekly Mon 03:00 UTC) -> the cron route.
  - app/[locale]/clinician/observations/page.tsx - "Sync to REDCap now" button
    + result/error, next to the existing "Download REDCap CSV".
  - messages/{en,da,sv,nb}.json - 5 new keys under clinician.researchExport
    (syncIntro/syncButton/syncWorking/syncResult/syncError). da/sv/nb are
    first-pass, flagged for native review.
  - redcap/AUTOMATION.md - architecture, env vars, limits, DPO gate.
  - docs/ROADMAP.md - REDCap sync marked BUILT.

YOU MUST SET (Vercel env vars, server-only, NO NEXT_PUBLIC_; Production):
  REDCAP_API_URL    your instance API endpoint, e.g. https://redcap.x/api/
  REDCAP_API_TOKEN  the project API token (a credential - never in code/zip)
  CRON_SECRET       any long random string (gates the scheduled route)
  Until these are set, both routes return 400 "REDCap not configured" - harmless.

SHAPE
  Full snapshot, chunked, idempotent. Incremental sync deferred. Cron runs on
  the production deployment only; weekly is fine on any plan (more-frequent-than
  -daily needs Pro). maxDuration=60 (Hobby caps lower; fine at current scale).

*** DPO/DPIA GATE ***
