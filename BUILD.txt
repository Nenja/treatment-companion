BUILD - sentry-enable-1   (turn Sentry on)

WHAT THIS IS
  Switches on error monitoring. Sentry does NOT need a custom domain - it works
  fine on your .vercel.app URL. The app was already wired for Sentry, but one
  piece was inert: browser-side error capture. This drop fixes that and gives
  you a step-by-step runbook for the dashboard parts (which are yours to do).

THE ONE CODE CHANGE (a file rename)
  Old: sentry.client.config.ts  ->  New: instrumentation-client.ts
  Why: without the Sentry build plugin (withSentryConfig, which we deliberately
  don't use), nothing loaded sentry.client.config.ts, so browser errors were
  never captured. Next.js loads instrumentation-client.ts natively, so renaming
  fixes it with no build changes. Server + edge were already fine.

FILES IN THIS DROP
  instrumentation-client.ts   NEW - browser Sentry init (was sentry.client.config.ts)
  instrumentation.ts          comment update only
  docs/SENTRY_SETUP.md        NEW - the dashboard runbook (read this next)

DEPLOY
  1. GitHub Desktop: add instrumentation-client.ts and instrumentation.ts, and
     **DELETE sentry.client.config.ts** (a zip can't delete it for you). Commit,
     push to main.
       -> Confirm sentry.client.config.ts is gone and instrumentation-client.ts
          is present in the repo.
  2. Then follow docs/SENTRY_SETUP.md to:
       - create an EU-region Sentry project (DSN ends ingest.de.sentry.io)
       - set NEXT_PUBLIC_SENTRY_DSN (required) and
         NEXT_PUBLIC_SENTRY_ENVIRONMENT=production (recommended) in Vercel
       - redeploy, confirm, and set the three alert rules
     Until a DSN is set, Sentry stays a safe no-op and captures nothing.

PRIVACY (already enforced, clinical-grade)
  sendDefaultPii:false; a beforeSend scrubber strips request bodies, cookies,
  headers, query strings, user ids, and breadcrumb URLs; no tracing/replay.
  ONE caveat (in the runbook): the scrubber can't clean PII written into an
  exception message itself - keep patient data out of throw/Error strings.
