  Cumulative repo snapshot on top of e2e-trigger-fix-1. ONE config change in

WHAT CHANGED (next.config.ts)
  The CSP header is now ENFORCED: the header key was renamed from
  `Content-Security-Policy-Report-Only` to `Content-Security-Policy`. The policy
  string itself is UNCHANGED — it already covered Supabase (REST + wss), Sentry
  ingest, self-hosted fonts, data/blob/https images, blob media + Supabase
  Storage, blob workers, and set frame-ancestors 'none' / object-src 'none' /
  base-uri 'self' / form-action 'self'. It retains 'unsafe-inline' (+ 'unsafe-eval'
  for scripts) because Next.js injects inline hydration code — so enforcing does
  NOT break framework code; it only activates the source allow-list and the
  clickjacking/object/base lockdowns. Doc comments updated to past tense.

  Not done (deliberate, P1 follow-up): the nonce-based policy that would let us
  drop 'unsafe-inline'. That's a larger, test-heavy change for the developer.

HOW TO VALIDATE (staging first — this is what staging is for)
  1. Upload to the `staging` branch -> open the Preview URL.
  2. With browser devtools open (Console), click through the main flows:
     patient (login, home, a check-in), clinician (unlock a patient, open the
     treatment screen, save), physiotherapist (rate a goal, add a note).
  3. Watch for red "Content-Security-Policy" / "Refused to..." console errors and
     for any broken styling, missing images, failed Supabase/Sentry calls.
  4. If clean, upload to `main` -> enforced in production.
  If something IS blocked, note the blocked URL/directive and send it to me;
  widening one directive is a one-line change. To revert entirely, re-upload the
  previous zip (e2e-trigger-fix-1).
