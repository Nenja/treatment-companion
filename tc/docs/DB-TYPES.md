# Typed database layer (Supabase generated types)

**Status: LIVE.** `lib/database.types.ts` is generated from the real schema and
the three Supabase client factories are typed `<Database>`, so every
`.from()`, `.select()`, `.rpc()`, insert and update is checked against the
actual schema at compile time. This is what catches schema/query drift (e.g. the
`m.guidance`→`s.guidance` rename in 0111) at build time instead of at runtime.

## The types
`lib/database.types.ts` (30 tables, 25 enums, 175 functions), generated via
Supabase's `postgres-meta`. Clients wired in `lib/supabase/{browser,server,
serviceClient}.ts`.

## Regenerating after a schema change
```bash
export SUPABASE_PROJECT_ID=<project ref>      # + SUPABASE_ACCESS_TOKEN
npm run gen:types                              # writes lib/database.types.ts
```
(`supabase gen types --project-id` uses the Supabase API — no Docker. The
`--db-url` mode needs Docker; this repo's file was generated by replaying the
migrations into a local Postgres and running `postgres-meta` directly, which
yields identical output.) Commit the regenerated file; run the full verify.

## Patterns used when adopting (for future query edits)
Wiring `<Database>` surfaced ~57 type mismatches, all resolved with no runtime
change. The patterns, in case you hit them again:

- **Nullable column → `undefined` domain field:** `row.x ?? undefined`.
- **RPC arg, optional param (`T | undefined`, SQL `default null`):** pass
  `?? undefined` instead of `?? null` — equivalent because the param defaults to
  null (verified per function).
- **RPC arg, required param (`T`, no SQL default) that legitimately takes null:**
  `(expr) as T`. Postgres accepts null for any param, but `postgres-meta` types
  no-default params as non-null; the cast preserves the exact value sent.
- **String → enum union (e.g. guidance, sex, etiology):** `expr as <EnumType>`.
- **PostgREST embedded selects** (`profile:profile_id ( display_name )`): the
  generator can't resolve the foreign table and types it as `SelectQueryError`.
  Route the access through `as unknown as { … }`. Not a runtime bug.

## CI guard (optional, recommended)
Add a job that regenerates types against the linked project and fails if the
committed file is stale (`git diff --exit-code lib/database.types.ts`). Needs
`SUPABASE_ACCESS_TOKEN` + `SUPABASE_PROJECT_ID` repo secrets.
